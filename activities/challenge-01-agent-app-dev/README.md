# 知识包 challenge-01：教 AI 学会「落地 agent 应用开发」

> 内容层唯一索引。机制层（会话决策 / 表达契约 / 纠错阶梯 / 掌握度闸门 / 人物融合）一律以源码为准，本包只提供源码机制可消费的内容：KP、资料、误解条目、引导步骤、逐日任务。
> 设计依据：`docs/specs/challenge-01-agent-app-dev-package.md`（v0.6 源码对齐版）。

## 主题与画像

- 一句话：用户用 17 天把「如何从零落地一个 agent 应用」完整教给 AI 学生；教会的证据进掌握度账本 = 挑战完成。
- 学习者画像：用过 LLM 聊天但没独立落地过 agent 的人；下限由零起点引导层（onboarding-d0.md）兜底。
- 实践线：D1-D2 先动手做四个对照实验，后续理论模块全部回扣亲手观察。

## 知识地图（8 模块 = KP 集合）

| 模块 | 核心内容 | 学会的判据（老师侧证据表现） |
|---|---|---|
| M0 动手体验 | 四个对照实验（纯 DeepSeek / zcode / Claude Code / Codex 同一任务）；观察 loop 行为 | 能基于亲手记录讲清 agent 和直接问 LLM 差在哪，举出具体一幕 |
| M1 场景与边界 | agent vs workflow vs 普通 LLM 调用；任务闭环定义 | 给具体场景能正确归类并说理 |
| M2 核心循环 | 感知→规划→工具→观察→迭代；终止条件 | 能手画 loop 讲每步输入输出，说出 3 种终止条件 |
| M3 工具设计 | 工具描述、参数 schema、数量控制、错误处理 | 能评审写差的工具定义并改对 |
| M4 上下文工程 | 系统提示结构、上下文预算、记忆分层 | 能指出臃肿 prompt 的问题并重写，给 2 种压缩策略 |
| M5 可靠性与纠偏 | 反思的边界、人机回环、幻觉控制 | 能说明反思何时空转、哪些动作必须问人 |
| M6 评测与迭代 | eval 集、指标、badcase 驱动 | 能设计 ≥20 条 eval 集结构并说分层理由 |
| M7 部署与运营 | 模型分级、超时重试限流、监控、灰度 | 能列上线 checklist 并解释每项防什么 |

## 17 天编排

- D1-D2：M0 实操（labs.md 四个 Lab）
- D3-D16：M1-M7 每模块两天（第 1 天讲透概念，第 2 天应用纠错）
- D17：综合验收
- 累计制打卡：断签不算失败；理论日 20-30 分钟，实操日 40-60 分钟。D0 不占打卡天数。

## 完成判据（草案，待 §10-1 拍板）

每个模块老师侧至少产出 1 条 transfer 或 correction 的 passed 证据；D17 验收产出 delayed_retrieval 证据；纯 explanation 不算完成。

## 文件结构

- `days/day-01.md … day-17.md`：逐日任务（front-matter 对齐 activity_tasks 字段）
