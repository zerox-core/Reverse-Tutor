## 1. 审计结论

Figma 正式总览下共有 21 个正式分区、56 个直接手机画板、182 个交互节点、187 条 reactions 和 10 个命名原型起点。逐一与当前 `mobile-native` Compose 路由、页面、状态、文案和已采集截图核对后：

- 正式稿匹配：`0 / 56`
- 错误实现：`13 / 56`
- 仅部分业务语义存在：`10 / 56`
- 正式页面或状态缺失：`33 / 56`

当前 Debug APK 只能证明旧 preview UI 可以运行和完成部分手势，不得再作为正式 Figma 落地或视觉验收证据。

## 2. 判定规则

| 状态 | 含义 |
|---|---|
| 匹配 | 信息架构、视觉、文案、状态和交互均可对应正式节点 |
| 错误实现 | 存在同名或相近入口，但页面结构或产品语义来自旧稿 |
| 部分存在 | 数据能力或局部交互存在，但正式画板状态、视觉或导航不完整 |
| 缺失 | 没有可到达的正式页面/状态，或仅有与正式稿无关的占位 |

空间交互以用户后续确认覆盖 Figma 旧连线：

```text
本周学习 <- 会话首页 -> 全局图谱 -> 社区
                 ^
               挑战页
```

该覆盖只定义空间关系，不授权添加 Figma 中不存在的全局四点指示器。页面可见指示按对应正式画板实现。

## 4. 跨页面错误

1. 当前实现仍使用旧的 15 页面规范，其中包含正式稿已删除的“学习大脑”。
2. `AppNavigation` 和 Drawer 仍暴露“学习大脑”，并把本周副屏映射到 `BrainScreen`。
3. 当前首页启动调用 `ensurePreviewSeed()`，生成 `Reverse Tutor preview` 等测试会话。
4. 当前底部全局四点指示器不属于正式画板；首页正式稿仅有主屏/本周双态提示。
5. 当前大量 UI 使用旧紫色 `#575CE6`、18dp 卡片和通用 Material 控件；正式稿使用不同的蓝色、8dp 以内卡片圆角及实体轻光泽图标体系。
6. 当前多处模板、角色和目标仍把 AI 定义成老师、导师或教练，违背反向教学产品定义。
7. 当前图谱使用圆周排列，违反层级锚点、引力/斥力、碰撞和惯性约束。
8. `FigmaResponsiveDeviceTest` 点击的是旧 preview 文案，只能证明错误 UI 可达。

## 5. 可保留边界

以下能力不因 UI 审计失败而推翻：

- Room、Repository、DAO、迁移、preferences 和 SecretStore；
- `core/model`、`core/protocol`、`core/llm`、`core/remote`；
- FastAPI 和 PostgreSQL 契约基础；
- 会话、消息、资料、图谱、世界树、导入导出和 TokenUsage 数据能力；
- `WorkspacePage.FixedOrder`、横向 Pager、挑战纵向 Pager、手势锁和图谱边缘翻页机制。

以下只能提取底层能力后重做 UI：

- `KnowledgeGraphUiState` 的选择、hit-test 和证据关联；
- `NativeGraphCanvas` 的缩放、平移和手势生命周期；
- 现有设置、导入导出、诊断和挑战状态适配器。

## 6. 新验收门槛

每个正式画板必须同时满足：

1. node-id 与 Compose route/state 一一登记；
2. 页面截图与对应 Figma 节点比较，不以“无重叠”替代设计一致性；
3. 标题、文案、控件、图标、颜色、圆角、间距和状态无未批准偏差；
4. `390 x 884` 逻辑基准、`1216 x 2688` Mate 60 参考尺寸和至少一个窄屏均无裁切；
5. 交互按正式原型和用户明确覆盖规则执行；
6. 未设计状态保持静态，不伪造功能；
7. 旧 preview 文案、旧“学习大脑”和无正式来源的组件从正式入口删除，不归档保留。
