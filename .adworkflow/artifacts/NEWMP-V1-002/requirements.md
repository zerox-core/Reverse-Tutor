# NEWMP-V1-002 · 引导式学习与会话学习笔记 Agent

## 问题

当前助手可能把系统资料引用混入聊天正文，且会话主要表现为自然语言输出，缺少可验证的学习动作、格式化内容和受限工具调用能力。

## 用户价值

用户获得自然的引导式学习对话；资料可独立查看或关闭；系统可在当前会话自动维护一份结构化学习笔记，而未来前端可独立决定资料、文档和轻量表格的表现方式。

## 已确认范围

- 学习模式迁移旧 `main` 的追问、反例纠错、线索、脚手架、检验和复盘规则。
- 目标/陪伴模式不写掌握度。
- 助手结果分离为正文、资料引用、学习结果和工具结果。
- 内容支持标题、段落、列表、代码块、提示和简单表格。
- 自动工具写入允许，但仅限当前会话的会话文档与轻量表格，且按调用 ID 幂等。
- 工具能力借鉴 DeepSeek Harness 的定义/注册/策略/执行/展示意图分层；不接入 DSH 运行时。
- Nous Hermes Agent 仅作为长期记忆架构参考。

## 非目标

- 不微调模型，不运行第三方插件或任意代码。
- 不访问设备文件、网络、系统命令、密钥或跨会话数据。
- 不复刻飞书多维表格 UI，不接入飞书 API。
- 不由当前前端页面或按钮决定后端契约。

## 依赖与审批门

实现富内容/工具载荷需要 P3 能力申请；实现文档、表格和调用回执持久化需要 P6 能力申请。批准前只能完成纯领域策略、测试、文档和申请，不得修改冻结生产层。

审批申请与责任边界：

- P3：`tasks/capability-requests/P3-rich-reply-evidence-and-tool-envelope.md`，负责生成协议侧的富回复、独立资料引用和工具调用信封。
- P6：`tasks/capability-requests/P6-session-document-table-and-tool-receipts.md`，负责会话文档、轻量表格、回复工件、调用回执以及 `10 -> 11` 前向迁移。
- 两项必须由用户分别明确批准；仅认可设计或执行计划，不等同于批准任一冻结层生产改动。

## 验收摘要

- 正文不再包含 `Sources:` 或原始系统检索信息。
- 学习策略与模型输出分离；无结构化证据不写掌握度。
- 工具只能操作当前会话；重复调用不重复写入。
- 工具失败不阻断聊天且不泄露内部信息。
- 自动化和主力机验证有真实证据。
