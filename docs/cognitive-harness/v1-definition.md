# V1 定义：认知 Harness 最小骨架

> 拍板日期：2026-10-27
> 前置文档：`cognitive-tool-matrix.md`（算子清单）、`education-methodology-tools.md`、`problem-philosophy-tools.md`
> 本文是这三份文档的**收敛结果**——从 40+ 候选算子落到可执行的一版。

---

## 一、V1 是什么 / 不是什么

**是**：一个能被真实教学对话撞墙的最小骨架。够薄、能跑、能看输出、能定位失败点。

**不是**：完整的教学系统、固定的教学管线、预先把所有学科都想清楚的大设计。

判断标准只有一条：**跑起来之后，能看出模型在哪一步判断错了、缺了哪类输入。**

---

## 二、两类实现形态（架构约束，非可选项）

| | Type 1 确定性能力工具 | Type 2 结构化推理骨架 |
|---|---|---|
| 形态 | 真实 function call | 提示词注入的强制输出结构 |
| 谁干活 | 宿主代码 | 模型自己判断，但必须按槽位输出 |
| 返回 | 客观事实，同入参同结果 | 结构化自检，填不出即不合格 |
| 换模型调用 | 结果不变 | 结果变，但结构不变 |

**判定门槛**（分错类的代价：把该模型判断的硬写成规则，每个都比模型更差，等于退回固定管线）

- 归 Type 1 需三条全中：① 结果不依赖语言理解 ② 可写单测断言 ③ 换模型结果不变
- 否则归 Type 2

**Type 2 不违反「禁止拆东墙补西墙」的判据**：
删掉它，模型的**输出结构**会退化 → 是骨架，合法。
只是某句话不再说了 → 是胶带，违规。

## 三、V1 的实际构成

### Type 1：34 个工具

**A. 已有学科知识层（31 个，未改动）** —— `CoreTools.kt`
事实检索 3 / 角色扮演 6 / 认知诊断 4 / 教学策略 5 / 决策路由 4 / 记忆管理 5 / 评估反馈 4

**B. 新增推理形式层（3 个）** —— `CognitiveTools.kt`

| 工具 | 确定性部分 | 输出 |
|---|---|---|
| `locate_missing_warrant` | 「显然/同理/易证」等标记词命中 + 同句/邻句是否有论证连接词 | 命中位置、被跳过的步骤、severity |
| `detect_fluency_illusion` | 应答词占比、因果连接词轮数、平均产出字数 | 0~1 风险值、触发信号 |
| `build_argument_graph` | 图算法：悬空节点 / 环检测 / 从证据出发的可达深度 | 悬空断言、循环论证、断裂链 |

### 为什么只加 3 个（去重记录）

新提出的 40 个算子里，6 个与现有 31 个**完全同构**，已合并、不新建：

| 原拟名 | 已有同构工具 |
|---|---|
| `search_course_material` | `search_materials` |
| `inspect_common_misconceptions` | `detect_misconception` |
| `record_student_mental_state` | `update_knowledge_graph` |
| `map_analogy_structure` | `suggest_analogy`（已含映射与局限性） |
| `construct_elenchus` | `challenge_teacher_explanation`（已含边界/反例/推广/变式） |
| `design_killing_test` | `design_counterexample` |

其余 30+ 个归 Type 2。

### Type 2：40 条骨架，7 个家族

`prompt/CognitiveScaffolds.kt`

| 家族 | 治的认知失败 | 条数 |
|---|---|---|
| F1 边界与失效 | 这套推演在哪个角落会崩 | 6 |
| F2 隐藏前提显影 | 什么被默认了却没说 | 7 |
| F3 具象与抽象配平 | 是不是在名词对飚 | 6 |
| F4 目标与验收 | 到底要抵达什么、怎么算抵达 | 3 |
| F5 节奏与负荷 | 一步跨多大、脚手架该不该撤 | 4 |
| F6 提取与流畅错觉 | 听懂了不等于学会了 | 5 |
| F7 问题的合法性 | 这个问法配不配得到答案 | 9 |

**注入方式**（不做 40 条全量背诵——会占 3000+ token 且稀释注意力）：

```
选: <骨架id,骨架id>      ← 从菜单选 1~3 条；没触发任何一条写「无」
判定: <按选中骨架的槽位逐条填>
动作: <基于判定，下一句要做的唯一一件事>
```

外层包 `<pedagogy_eval>`，与既有 `<thinking>` 分工：
- `<thinking>`：第一人称内心独白（人设层，自由发挥）
- `<pedagogy_eval>`：结构化判定（骨架层，字段固定）

「写不出槽位 → 说明该骨架不适用，换一条」——这条规则是防硬凑的关键。

## 四、本版一并清掉的技术债

**删除**：`PromptAssembler.kt` 里硬编码的「数学正确性（最高优先级）」三行：
- `x² + bx = (x + b/2)² - (b/2)²`
- `顶点横坐标是 -b/(2a)`
- `二次函数要求 a ≠ 0`

这是针对**单个知识点**的错误写的提示词胶带。换学科零作用，占注意力，且违反用户红线。
替代物：`F5.step`（步长粒度）+ `F2.warrant`（跳步定位）+ Type 1 符号检查（待补）。

**保留**：`make_deliberate_mistake` 的「故意犯错不算错误」说明——那是工具语义，不是学科补丁。

## 五、V1 的验证方式

**不看**：单元测试绿不绿（那只能证明代码没崩）。
**看**：真实教学对话跑起来后，模型选的骨架对不对、判定填得实不实、学生的反问是否真的落在对方的漏洞上。

第一个试验田（用户指定，其最熟悉领域）：**高中数学 · 解析几何大题**。
样本见 `sample-parsing-geometry-round1.md`。

**撞墙时怎么改**（错误驱动开发）：

| 症状 | 对症改法 | 禁止改法 |
|---|---|---|
| 模型不选骨架 | 检查菜单里对应条的 `trigger` 是否写成可判定条件 | 加一句"你必须选择骨架" |
| 选了但槽位乱填 | 把槽位定义得更具体（现在是名词短语，可能需改成问句） | 加一句"要认真填" |
| 该选的没选 | 补一条 trigger 更宽的骨架，或合并两条 | 给某个具体学科加特例 |
| 选太多、每轮 5~6 条 | 契约里把上限压到 1~2 | —— |

**每条改动的验收**：改完能不能说出「这治的是哪一类失败」。说不出就是胶带，撤回。

## 六、明确不在 V1 范围内

- 知识图谱自动生长（用户指示先不管）
- 难度设置接入（probingIntensity 等）
- `SessionTurnPolicy` 那套死掉的状态机（已被否决，不接）
- L2 的 `[REJECT_JARGON]` / `[PROBE_GAP]` 等动作码枚举（暂由骨架 F2/F3 覆盖其意图）
- 创建链路的 Builder Agent 大纲编译（另一条线，等会话侧跑通再谈）
