# NATIVE-UX-009 · 资料库解析状态与恢复规范

## 目的与边界

本规范固定资料库对文件处理结果的表达：用户能知道文件是否可用、当前影响是什么、是否可以再次处理，以及图片资料与聊天附件能力的边界。

本任务只约束 `feature:sources` 的 presentation state、资料卡和设备验收。`SourceParserStatus`、`SourceRepository`、Entity、DAO、Room、解析器、导入协议、LLM、PWA 与 Capacitor 均保持不变。

## 状态与恢复矩阵

| 状态 | 状态标签 | 用户影响 | 恢复动作 |
|---|---|---|---|
| FullyLocal | 已解析 | 已有片段，可用于上下文与引用 | 重新解析 |
| PartiallyLocal | 部分解析 | 已提取部分内容，使用前需查看警告 | 重新解析 |
| FutureAssisted | 等待能力 | 文件保留，当前设备没有对应解析能力 | 不显示解析按钮；打开资料库查看限制 |
| Unsupported | 暂不支持 | 文件保留为参考，当前版本无法处理 | 不显示解析按钮；显示不支持原因 |
| Failed | 失败 | 文件保留，解析尝试失败 | 重试 |

恢复动作必须由现有 `SourceRepository.reprocessSource` 能力决定：等待能力和暂不支持不能因为 UI 出现按钮而获得不存在的解析能力。失败使用“重试”，已解析和部分解析使用“重新解析”，避免把两种语义混为一谈。

## 资料卡层级

每张资料卡固定按以下顺序显示：

1. 文件标题、文件类型、状态标签；
2. 处理结果与影响说明；
3. 片段数量和最多两条片段预览；
4. 资料引用可用性；
5. 可执行的恢复动作，或不可执行原因。

所有状态都必须保留在列表中。没有片段时显示“尚无可引用片段。”及保留原因，不留下空白区域。没有恢复能力时显示限制原因，不显示点击无反应的按钮。

状态颜色只能辅助文字：已解析、部分解析、等待能力、暂不支持、失败必须通过标签和说明区分，不能只用色彩表达。

## 图片资料与聊天附件边界

图片资料属于资料库对象，当前 `FutureAssisted` 时应说明“图片资料会继续保留，等待视觉解析能力”。这不等价于聊天附件能力；聊天页面拥有独立的附件支持和失败反馈。资料库不得暗示图片已经产生可引用片段，也不得因聊天支持附件而改变资料解析状态。

## 导入与重试反馈

- 文件导入后在“最近导入”面板显示标题、类型、状态、片段数、警告和错误。
- 点击重新解析或重试后，资料卡保持在原列表位置，面板显示本次 `SourceImportResult` 的实际状态。
- 失败重试不得隐藏原文件、清除旧的可用片段或伪造成功；所有结果均来自现有 Repository 返回值。
- Context Hub 通过真实 `sourceId` 进入资料库时，高亮对应 `source-card-<id>`；普通进入资料库不保留过期高亮。

## 无障碍与自适应

- 添加资料、选择文件、恢复动作均至少 48dp；卡片状态和恢复原因按 TalkBack 阅读顺序位于标题与片段之后。
- 资料卡可以在大字号下换行，状态标签和恢复按钮不得互相遮挡。
- 深色模式下五种状态仍需有足够文字和语义色对比；不能用纯红/绿作为唯一区分。
- 不支持或等待能力的状态也必须可被辅助技术读到原因与下一步。

## 验收映射

- `UI-S-001`：标题、类型、解析状态、片段/引用信息和资料上下文。
- `UI-S-002`：五种解析状态的明确标签与影响说明。
- `UI-S-003`：部分、等待、不支持、失败文件均保留；恢复动作只在能力真实存在时出现。
- `UI-S-004`：图片资料状态与聊天附件能力独立表达。
- `UI-A-001`、`UI-A-002`、`UI-A-004`、`UI-A-005`：触达区、阅读顺序、大字号和深色模式要求。

UX-009 是资料库表现契约，不修改解析能力，不更新覆盖登记为已验证，也不宣称 Phase 5 或 PWA 替换准备完成。任何新增解析能力必须另行走后端/冻结层契约审批。
