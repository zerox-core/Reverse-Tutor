# NATIVE-UX-007 · Context Hub 信息架构与证据呈现规范

## 目的与边界

Context Hub 是从当前聊天会话进入学习证据的唯一入口。它帮助用户回答三个问题：当前会话积累了什么、每条学习记录依据什么、下一步可以回到哪里继续处理。

本规范仅定义信息架构、对象分组、证据摆放与页面流。它不改变 `MemoryRepository`、`GraphRepository`、`SourceRepository`、Room、协议、LLM、PWA 或现有的路由语义。现有 `Chat -> ContextHub` 回退到聊天的行为保持不变。

## 架构裁决

1. Context Hub 按“会话概览 → 证据对象 → 深入处理”的层级组织，不把资料库、图谱或设置的完整功能复制到本页。
2. 证据动作只使用记录中已存在的 `sourceMessageId` 或 `sourceId`。目标 id 缺失时不显示动作，不得生成猜测性跳转。
3. 图谱保持原生 Canvas 与已有的可访问节点列表；Context Hub 只提供会话范围的图谱入口和节点证据出口。
4. 当前已连接会话、无会话、空记录、解析延后、加载失败是不同状态，必须分别说明原因、影响和可执行的下一步。

## 页面层级

### 一级：会话身份与概览

页面顶部固定表达当前会话名称和连接状态。概览是首个分区，显示锚点、随笔、错误和图谱的计数，以及一条简短的会话学习摘要。概览只用于定位，不承载每条记录的详情。

无活动会话时，顶部明确说明 Context Hub 需要从某个聊天会话进入；仍可看见各分区名称，但不显示不存在的记录或虚构的恢复动作。

### 二级：六个分区

分区顺序固定为：概览、图谱、锚点、随笔、错因、会话设置。

| 分区 | 主要对象 | 本页承载内容 | 深入处理位置 |
|---|---|---|---|
| 概览 | 会话摘要 | 计数、当前连接状态、下一步提示 | 对应分区 |
| 图谱 | 会话图谱节点 | 图谱状态、Canvas、节点详情、关联证据 | 全局图谱或聊天/资料库 |
| 锚点 | 学习锚点 | 标题、正文、关联聊天/资料来源 | 聊天或资料库 |
| 随笔 | 会话随笔 | 标题、正文、关联聊天来源 | 聊天 |
| 错因 | 已解决或待处理的错因 | 标题、详情、解决状态、关联聊天来源 | 聊天 |
| 会话设置 | 当前会话配置 | 当前可用设置入口与说明 | 会话设置页 |

分区选择器是页面内切换控件，不改变应用的主导航层级。页面底部保留“返回聊天”为主动作；全局图谱、资料库和设置为次级动作，不与主动作争夺视觉优先级。

### 三级：证据条目

锚点、随笔与错因中的每个条目按以下顺序显示：

1. 标题与可用状态；
2. 正文或说明；
3. 证据引用动作；
4. 该分区的下一步提示。

一条记录可以同时包含聊天证据与资料证据，两个动作并列显示且各自只跳转到自己的目标。动作文案为“打开关联聊天证据”与“打开关联资料证据”。没有引用时，不显示空按钮；正文下改为说明该条目当前没有可跳转的证据。

## 证据流与返回语义

```text
聊天
  -> Context Hub
     -> 锚点 / 随笔 / 错因 -> 关联聊天证据 -> 聊天
     -> 锚点 -> 关联资料证据 -> 资料库（高亮对应资料）
     -> 图谱节点 -> 关联聊天或资料证据 -> 对应目标
     -> 会话设置 -> 会话设置页
     -> 返回聊天 -> 原会话聊天
```

资料库高亮只在已传入真实 `sourceId` 时生效；进入普通资料库时不保留过期高亮。Context Hub 不承担“返回上一证据条目”的第二套导航栈：系统返回遵从既有应用路由，明确的“返回聊天”始终回到发起 Context Hub 的会话。

## 状态矩阵

| 场景 | 用户可见说明 | 可执行动作 |
|---|---|---|
| 无活动会话 | 尚未连接会话，无法显示会话证据 | 返回聊天或打开会话 |
| 分区为空 | 该类记录尚未形成，说明会如何产生 | 返回聊天，或在图谱中创建证据 |
| 图谱加载中 | 正在读取当前会话图谱 | 等待，不展示旧节点冒充新结果 |
| 图谱错误 | 未能读取图谱，不影响已有聊天和资料 | 重试、返回聊天 |
| 图谱无效或过大 | 解释图谱状态并提供可访问节点列表 | 查看节点详情、打开关联证据 |
| 资料证据不存在或无片段 | 资料仍保留，但无法定位到片段 | 仅打开资料库；不承诺片段跳转 |
| 来源解析延后或不支持 | 说明资料保留和当前能力限制 | 打开资料库查看状态；不显示无效重解析 |
| 错因已解决 | 显示已解决状态，不隐藏历史依据 | 打开关联聊天证据（若存在） |

## 无障碍与视觉规则

- 分区、证据动作与底部导航动作均有不小于 48dp 的触达区域。
- TalkBack 顺序与页面阅读顺序一致：会话身份、概览、分区选择、条目内容、证据动作、底部动作。
- Canvas 不是图谱的唯一阅读路径；大图或无法使用手势时必须可通过节点列表和详情进入证据。
- 状态颜色只能补充文字，不可单独表达“成功、警告、延后、失败或已解决”。
- 深色模式和大字号下，证据动作可换行，但不得覆盖标题、正文或返回聊天动作。

## 验收映射

本规范满足并细化以下既有验收项：

- `UI-M-001`：六个分区的存在与层级；
- `UI-M-002`：聊天/资料证据的真实目标与返回路径；
- `UI-M-003`：无会话、空、加载、错误、延后和大图谱状态；
- `UI-A-001`、`UI-A-002`、`UI-A-004`、`UI-A-008`：触达范围、阅读顺序、大字号与非 Canvas 路径。

UX-007 是规格任务，不将任何覆盖登记标为已验证，也不宣称 Phase 5 或 PWA 替换准备完成。若后续 UX-008、UX-009 或 UX-010 发现现有实现与本规范不一致，应以对应垂直切片补测试和最小 UI 修复，而不是修改冻结层来适配页面。
