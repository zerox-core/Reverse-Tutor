## 1. 主题定位（内容层）

- **一句话**：用户用 17 天把「如何从零落地一个 agent 应用」完整教给 AI 学生，教会的证据进掌握度账本 = 挑战完成。
- **学习者画像**：用过 LLM 聊天但没独立落地过 agent 的人；下限由零起点引导层（§7）兜底。
- **实践线**：前 2 天先动手（zcode+DeepSeek API / Claude Code / Codex 对照实验），后续理论模块全部回扣亲手观察。

## 2. 知识地图（内容层：8 个模块 = KP 集合）

| 模块 | 核心内容 | 学会的判据（老师侧证据表现） |
|---|---|---|
| M0 动手体验 | 四个对照实验（纯 DeepSeek / zcode / Claude Code / Codex 同一任务）；观察 loop 行为 | 能基于亲手记录讲清 agent 和直接问 LLM 差在哪，举出具体一幕 |
| M1 场景与边界 | agent vs workflow vs 普通 LLM 调用；任务闭环定义 | 给具体场景能正确归类并说理 |
| M2 核心循环 | 感知→规划→工具→观察→迭代；终止条件 | 能手画 loop 讲每步输入输出，说出 3 种终止条件 |
| M3 工具设计 | 工具描述、参数 schema、数量控制、错误处理（解剖 Claude Code 真实工具集） | 能评审写差的工具定义并改对 |
| M4 上下文工程 | 系统提示结构、上下文预算、记忆分层 | 能指出臃肿 prompt 的问题并重写，给 2 种压缩策略 |
| M5 可靠性与纠偏 | 反思的边界、人机回环、幻觉控制 | 能说明反思何时空转、哪些动作必须问人 |
| M6 评测与迭代 | eval 集、指标、badcase 驱动 | 能设计 ≥20 条 eval 集结构并说分层理由 |
| M7 部署与运营 | 模型分级（DeepSeek vs Claude 真实价差）、超时重试限流、监控、灰度 | 能列上线 checklist 并解释每项防什么 |

每个模块拆成若干 KP（知识点），KP 是掌握度账本与图谱投影的最小粒度；具体拆分在内容填充阶段定。

## 3. 分天骨架（内容层编排：17 天）

- D1：M0 实操上——Lab A 纯 LLM 基线（直接问 DeepSeek 写「统计日志错误数量」脚本，手工复制/运行/贴报错，记录「我手工做了哪些事」）+ Lab B zcode（配 DeepSeek API）同一任务
- D2：M0 实操下——Lab C/D Claude Code、Codex 同一任务，对比交互/工具集/速度/成本；把「差在哪」讲给 AI 学生
- D3-D4 M1、D5-D6 M2、D7-D8 M3、D9-D10 M4、D11-D12 M5、D13-D14 M6、D15-D16 M7（每模块第 1 天讲透概念、第 2 天应用纠错）
- D17：综合验收——AI 学生独立输出完整 agent 应用设计方案讲给「零基础第三者」，用户按 checklist 评分
- 累计制打卡（需求 D4 定案）：断签不算失败；理论日 20-30 分钟，实操日 40-60 分钟。**D1 前必须先完成 D0 起点测评与环境向导（§7），不占打卡天数。**

## 4. 误解内容条目（内容层：喂给源码纠错机制）

**机制以 `misconception-correction.md` 为唯一准绳**：评估字段 `evaluation.misconception`（≤20 字假规则）→ `challenge` 动作 + `confused_student` 角色 → L1 反例 → L2 指矛盾 → L3 求证式提示 → L4 一起验证，升级节奏由 `correction_persistence`（gentle/balanced/persistent，默认 balanced）与 `correction_timing` 控制；收尾 aha + `correction` 证据 `passed` + error_log resolved。本文不设计任何新机制。

本文贡献的是**内容条目**（10 条），每条 = 该 KP 的典型假规则（≤20 字，可直接匹配 evaluation.misconception）+ 最小反例素材 + 标准答案要点 + 关联 KP + 内容编排建议暴露时机（最终以动作引擎决策为准）：

| 条目 | KP | 假规则（≤20 字） | 标准答案要点 |
|---|---|---|---|
| E9 | M0 | agent 工具就是更聪明的自动补全 | 补全单次预测无循环；agent 是 loop（用 Lab 亲眼所见举证） |
| E10 | M0 | 有 Claude Code 就不用懂原理 | 不懂原理无法验收产出、无法纠偏（埋 M5/M6 钩子） |
| E1 | M1 | agent 就是给 LLM 写个好 prompt | 本质是 loop+工具+状态，prompt 只是一环 |
| E2 | M1 | 定时跑的流程也是 agent | 判据：路径是否由模型运行时决定 |
| E3 | M3 | 工具全塞给它自己会挑 | 工具过多稀释注意力；个位数到十几个为宜 |
| E4 | M4 | 上下文窗口大就全塞进去 | 噪声稀释+成本爆炸；裁剪/摘要/分层注入 |
| E5 | M5 | 让它自己反思几遍就不会错 | 无外部验证的反思是空转，放大自信幻觉 |
| E6 | M6 | demo 跑通就能上线 | demo 只证 happy path；需 eval/重试/成本延迟预算 |
| E7 | M7 | 全用最贵模型效果最好 | 模型分级路由；成本差一个数量级（回扣实操账单） |
| E8 | M7 | 上线后出问题看日志就行 | 无结构化监控等于裸奔；监控是实时发现 |

## 5. 掌握度与完成判据（源码对齐重写）

**账本方向（源码事实，`mastery-evidence-weighting.md`）**：`upsert_mastery` 记的是**用户（老师）对每个 KP 的掌握度**，不是 AI 学生的。证据分 `_EVIDENCE_SCORES`（none=0 / explanation=35 / retrieval=55 / transfer=72 / delayed_retrieval=82 / correction=90）；闸门=证据非 none 且 passed/partial（partial×0.75）；`alpha=0.35` EMA；failed 回退；「嘴上说懂」（none）不涨分。账本代码持有，模型只读不写。

- v0.2 的「AI 学生 8 条掌握度维度、初始 0、≥0.8 算教会」**作废**：AI 学生的「学习表现」是渲染层投影，不是账本。
- **挑战完成判据（草案，待与算法层对齐拍板）**：每个模块老师侧至少产出 1 条 `transfer` 或 `correction` 的 passed 证据；D17 验收产出 `delayed_retrieval` 证据；纯 explanation 不算完成。
- AI 学生外显的「学会程度」= 老师账本的**前端投影**（图谱/小组件），投影规则见 `docs/specs/graph-memory-projection-decisions.md`，本文不设计。

## 6. 对话策略（机制全引用源码；本文只补内容层约束）

- **表达契约**（`expression-loop-llm-first.md` §4.2）：像真人聊天、称呼老师自然克制绝不句句带、不先总后分不逐条罗列、允许犹豫与自我修正、废话不是失误、一轮最多一个问题。**本文此前所有示例话术（句句「老师」开头）与该契约冲突——内容填充时全部重写：只保留「学生向老师请教」的角度（意图），不保留称呼密度与固定句式。**
- **密度与节奏**（同 §4.5 + TurnNote）：低/中/高三档（≤80/160/300 字、新概念预算、questionBudget）、降档信号（连续高档/短消息/情绪词）、升档信号（用户主动要求展开/讲解/考试）。v0.4「节奏原则」作废，源码已完整覆盖且可执行。
- **深度**：`depth` 是老师讲解的评估维度（进 mastery 调用参数）；AI 输出深度由密度档控制；「用户自己深挖才加深」= 升档信号。v0.4「深度阶梯」作废；内容层的先浅后深体现在 §3 模块编排顺序里。
- **纠错**（`misconception-correction.md`）：L1-L4 阶梯 + persistence 档位，直接引用。收尾 aha 与情绪价值已在源码收尾设计中（含「被你说通了，谢谢老师」式高光）。
- **递话（R9 实证改判：源码缺口，需要补充）**：v0.6 曾判「L3/L4 已完整覆盖、作废」——实证不成立。L1-L4 阶梯的触发前提是检出 `evaluation.misconception`（老师**讲错了**）；而 R5 用户原话的场景是「老师太呆**说不到点上**」——没讲错、只是卡壳讲不出来。docs 全库检索「卡住/stuck/卡壳/讲不下去」仅命中 UI 等待态与我方文档，源码对「老师卡壳」**没有任何机制**。故递话从「作废」改判为**源码没有、需要补充的机制**：意图定义保留（卡住 → AI 递候选表述请老师确认 → 确认即视为有效教学 → 圆场不点破 + 情绪价值），风格按角色卡配方渲染；接法（新动作 vs 并入现有动作族、触发信号怎么定）不自行设计，列入 §10-6 待用户拍板。
- **意图/风格分离（保留，映射到源码分层）**：意图 = 动作与决策（代码层 SessionTurnPolicy / TeachingActionSelector / TurnNote），风格 = persona 渲染（`character-fusion-system.md`：性格底子/小怪癖/口头禅 + 权重跃迁 + 动态演化）。本活动固定角色卡 = 一套人物融合配方（预设词组+权重）。「以问引答」归入意图层（ask/probe/challenge 动作族本就以此运作）；语气、称谓、口头禅归入风格层配方。
- **引导交互（内容层新增，接线待算法层对齐）**：D0 测评与环境向导的「一步一确认」应映射为密度低档 + questionBudget=1 的会话状态；具体接线方式不自行设计，列入对齐清单。

## 7. 零起点引导层（内容层保留）

设计前提与降级铁律不变：不甩链接、不甩命令；一步一确认；报错对照卡；国内直连中文资源优先；实操深度可降、教学闭环不断。

- **D0 起点测评**：意图层四条（风格无关）——探明操作系统 / 终端经验 / 网络环境 / 已有装备（API key、开发者账号）。风格渲染按角色卡配方 + 表达契约生成（称呼克制），示例话术在内容填充阶段按契约重写。测评结果写入会话状态，引导按分支走，用户后续透露的信息实时修正分支。
- **降级链**：L1 完整实操（4 Lab）→ L2 部分实操（≥2 个对照，其余看演示）→ L3 零安装（网页版 DeepSeek 基线 + 预录录屏当观察员）。完成判据不因档位降低（判的是「讲得清差在哪」，见 §5）。
- **劝退点预案**：注册绑手机/实名/充值/英文页/下载慢/命令报错六大点，向导剧本预置话术；运营后台监控各步骤卡住率。
- **实测清单（内容填充前必须核实）**：DeepSeek 平台注册/实名/额度政策、zcode 获取与 DS API 配置、Claude Code 与 Codex 国内可达性、各镜像源可用性。实测不通的路线在向导里标记「走降级」。
