## 1. 背景与问题

### 1.1 用户反馈（原话要点）
1. 「他每句话都会用老师来开头，我会感觉非常奇怪。」
2. 「每句话都是先说一句大概，然后再介绍细节，跟豆包一样。」
3. 「内容太僵硬了，不像聊天的感觉。」
4. 「信息密度不能过大……我们是要有很多废话的……频率也要控制好。」
5. 「副文本状态是还行的，挺好的。」——「本轮学习提示」UI 保留不动。
6. 实际体验思考时间过久。

### 1.2 根因（均已代码核实）
- **结构硬规则写在提示词里**：`core/llm/.../LlmGenerationLifecycle.kt:676` `reverseTutorStudentPromptBlock()` 规定「举例子最多 5 步、每步一句话、用『→』衔接」「最多三小段或四短行、关键词 **加粗**」——直接产出先总后分的模板腔。
- **称呼被指令固化**：`core/llm/.../LlmStudentExpressionPolicy.kt` 中文指令集逐条以「老师」为称呼对象，且 `clue` 明文规定「用『老师，据说……』或『老师，我听说……』开头」。
- **每轮证据灌注**：`ConversationContextAssembler` 六类证据（摘要/近期消息/记忆/掌握度/资料/缺口/复习点/历史错误），经 `SessionPolicyInputMapper` 压成最多 6 条 × 900 字，再加三个策略块（turnPlan / guidedPlan / sessionPolicy）——每轮 prompt 达数千 token。
- **模型选型**：种子库 `llm_profiles` 主力 `deepseek-v4.1-flash`（enabled=1，2026-09-19 切换），备用 `glm-5.3` / `qwen3.8-max-0902` / `kimi-k3`（备用条目未启用）；baseUrl 为阿里云 MaaS 北京端点。
- **决策层不是延迟来源**：`SessionTurnPolicy`（纯规则引擎，老 engine.py 迁移）与 `TeachingActionSelector`（白名单 + 六维加权 0.30/0.25/0.15/0.15/0.10/0.05 + 硬规则优先 + 固定优先级破平）均为本地纯函数，微秒级。**减法不删决策层。**

## 2. 设计原则（分工线）

1. 做什么（动作 / 顺序 / 状态流转）→ 代码，已有，保留不动。
2. 账本（掌握度 / 记忆 / 错误记录）→ **代码持有，模型只读不写**。红线。
3. 输出硬红线 → 代码后置校验，命中重写一次；再失败走强约束备选 prompt 兜底。
4. 风格 / 语气 → 原则式提示词 + 下一轮便签纠偏，**不当场拦截**（避免第二次模型调用吃掉省下的延迟）。
5. 密度 / 节奏 → 代码给预算与降档信号（许可 + 上限），模型决定怎么用；不做节拍器式强制插入。
6. 减法优先：先减 prompt 灌注与结构规则，再谈新增组件。
7. 单模型优先：主流程只依赖用户配置的那一个模型；任何「第二个模型」的能力都只能是可选增强，且必须经用户授权（2026-09-19 用户拍板）。

## 3. 目标每轮链路

```
用户消息
  → ① 轻前置（代码，毫秒级）：人设/会话模板 + 最近 N 轮原文 + TurnNote 便签
  → ② LLM 开放生成（流式；envelope 含 独白/正文/自评 三段）
  → 并行：
      ③a 正文流式渲染进气泡（这就是最终回复，见 §3.1）；独白入思考链抽屉
      ③b 后台：ReplyValidator 校验 + 自评回写账本 + 轮后评估
  → 红线命中（罕见）：④ 流式中断 + 强约束备选 prompt 重新生成一次（见 §3.1）
  → 仍失败：⑤ 模板化降级回复 + 记录告警
```

### 3.1 澄清：不存在「用户看完再撤回换定版」
- ③a 流式渲染出来的**就是最终回复**，风格校验（称呼/结构/密度）只记录、写入下一轮便签纠偏，**永不对已显示内容做撤回或替换**。
- 红线（泄露教学策略、切讲课腔等，预期罕见）的处理也不是「看完撤回」：校验器**边收流边检**，命中即**中止当前流**——气泡停在未完成状态并提示「小K重新组织了一下语言」，随后用强约束 prompt 重新生成一条。用户看到的是「说到一半打住重说」，不是看完被换掉。
- 若连「中断重说」都不接受，可降级为：红线也只记录不重说（最彻底的无撤回），见 §8 待决项。

## 4. 组件设计

### 4.1 TurnNote 便签（新增，`core/domain`，非冻结层）
每轮由纯函数生成，字段：
- `learningStatus`：当前知识点 + 掌握度一行 + 上次错误一行（来自账本快照）
- `suggestedFocus`：建议方向一词（来自动作引擎输出，不展开成指令）
- `densityTier`：低 / 中 / 高三档
- `questionBudget`：0 或 1
- `paceSignals`：连续高密度轮数、用户消息过短、情绪词命中等真实信号
- `styleHint`：上一轮 ReplyValidator 的风格记录（如「称呼过频」）

### 4.2 新学生表达契约（原则式，替换 676 行现有契约）
保留：学生身份与反转教学定位、教学策略隐身、一轮最多一个问题。
删除清单：
- 「举例子带具体数字或函数、最多 5 步、每步一句话、用『→』衔接」
- 「最多三小段或四短行；关键词 **加粗** 突出」
- `LlmStudentExpressionPolicy.sessionPolicyDirectiveFor("clue")` 的「老师，据说……」固定开头
新增原则：
- 像真人聊天：不每轮同一种开头；称呼老师自然克制，绝不句句带
- 不先总后分、不逐条罗列；句子长短混搭，允许犹豫与自我修正
- 这一轮可以只是听，可以不推进任何东西；废话不是失误

### 4.3 ReplyValidator 后置校验器（新增）
- **红线（流式中边收边检，命中中断重说一次）**：泄露教学策略/计划、切换成讲课腔（以权威身份给完整解法）、自称人类、协议外内容。重写用强约束备选 prompt，仅一次。
- **风格（只记录，不拦截）**：「老师」称呼频率、总起句模式（先概括后分点）、箭头/分步结构、超密度预算、问题数 > 1。记录写入下一轮 `TurnNote.styleHint` 纠偏。

### 4.4 账本边界与轮后评估（单模型优先，2026-09-19 拍板方向）
- 掌握度 / 记忆 / 错误记录仅代码写入；模型任何输出不直接触账。
- **默认零额外调用**：主模型在本轮生成的 envelope 里顺手附一段结构化自评（本轮知识点、证据类型、验证状态；若现有 envelope 已有评估字段则直接复用），代码解析后按现有证据闸门规则回写账本——不增加任何额外模型请求，与市面单模型 agent 的速度/链路均衡一致。
- **可选增强「轻量模型精评」**：设置页检测用户 key 对应平台是否有可用的便宜模型 → 检测到则弹授权说明（「检测到你的 key 可用轻量模型，可为每轮增加一次低成本精评」）→ **默认关，用户同意才启用**；用户不开或没有可用模型时，主流程完全不受影响。

### 4.5 密度与节奏（默认草案，E2E 实测后调）
- 低档（陪聊/消化）：≤ 80 字、0 个新概念、问题预算 0~1
- 中档（默认）：≤ 160 字、≤ 1 个新概念、问题 1
- 高档（攻坚/验收）：≤ 300 字、≤ 2 个新概念、问题 1
- 降档信号（真实触发，非节拍器）：连续 3 轮高档 → 下一轮给中档许可；用户消息 ≤ 15 字 → 降一档；命中情绪词 → 低档。
- 升档：用户主动要求展开 / 讲解 / 考试时。
- 学习模式白名单对 `observe` / `emote` 类空动作开放，允许「这一轮只是听」。

### 4.6 延迟预算与模型选型
- 「模型主力」= 每轮对话实际调用的那个模型（当前为 deepseek-v4.1-flash，§8 决策④）。
- 现状归因（估算模型，待实测）：调用耗时 ≈ prefill（数千 token 证据灌注）+ decode（契约逼出的长结构化输出）；kimi-k3 大杯进一步放大。
- 目标（草案）：首 token ≤ 3s（Wi-Fi）、完整回复 ≤ 10s、单轮 prompt ≤ 1500 tokens。
- 选型矩阵：`kimi-k3` / `deepseek-v4.1-flash` / `glm-5.3` / `qwen3.8-max-0902`，维度 = TTFT / 生成速率 / 原则式指令遵循 / 成本；方法 = 同一便签 prompt × 固定 3 条测试消息实测，实测后定主力。
- 基线：实施前先在现有 memtest 包打点（TTFT / 总时长 / prompt tokens），改后对比。

### 4.7 思考链抽屉（已定稿：路线 C，2026-09-19 用户拍板）
气泡下挂一个可折叠「思考链」小抽屉，UI 在 `feature/*`（非冻结层）。
- **采用路线 C · 学生内心独白**：同一次生成里，模型先写一小段第一人称独白（「我卡在货币乘数这……想先问清楚……」），envelope 分隔标记与正文拆开；正文流式进气泡，独白进抽屉。
- 独白不过红线校验：红线只管说出口的正文（§10 决策⑨）；独白抽屉默认折叠、不触发拦截/重说/兜底，仅作 Trajectory 排查参考。
- 与 §4.4 自评字段共用同一次 envelope，零额外请求。
- 否决项记录：A 模型原生 reasoning（内容不可控、可能泄露策略）；B 纯内循环摘要（不像思考）——后续若用户要「系统视角」可作为抽屉底部一行追加，非本期。

### 4.8 缓存友好布局约束（2026-09-19 拍板，吸收 Codex / DeepSeek 前缀缓存机制）
每轮 prompt 按内容稳定度排序，稳定在前、变动在后，对齐 DeepSeek API 硬盘缓存（按完整前缀单元命中）：
1. 人设 + 会话模板 + 学生表达契约（跨轮一字不动；禁止注入时间戳、轮次号、动态统计数等任何每轮变化的内容）；
2. 会话摘要（低频更新：掌握度变化或每 N 轮才重算；摆放位置固定，作稳定中段）；
3. 最近 N 轮对话原文（append-only，只追加、不回改）；
4. TurnNote 便签 + 当前用户消息（每轮都变，永远放最后）。
- 依据：Codex 官方「缓存命中让采样从平方变线性；静态内容放前、变量放后、工具定义保持一致」；DeepSeek 官方缓存按完整前缀单元命中，前缀任一处变化即整体失效。预期效果：人设 + 契约 + 历史对话的大头 prefill 命中缓存，TTFT 与成本同步下降。
- 验证：切片 5 实测 usage 缓存命中字段（官方 DeepSeek 接口为 prompt_cache_hit_tokens / prompt_cache_miss_tokens；百炼兼容端点是否透传待实测，无则退化记录 input_tokens + TTFT）。
- 配套：turn_runs 表接线每轮 Trajectory（便签 / 模型输出 / 校验结果 / 自评落库，支持回放排查），归切片 3 范围。

## 10. 补充决策（2026-09-20 拍板）
- ⑨ 红线只管「说出口的正文」，不管内心独白/思考链：思考链抽屉（切片 4）默认折叠，独白即使暴露教学策略也不拦截、不触发重说/兜底——用户知道 AI 在陪演，能理解独白内容；真正要保护的只有学生直接看到的正文。
- ⑩ 兜底话术必须低频：红线中止 + 重说仅限正文真泄露的场景；「我刚把自己绕进去了」出现频率纳入切片 5 实测观察项，若 turn_run_trajectories 统计显示命中率过高，优先回头调红线清单与 prompt，而不是加码拦截。
- ⑪ 生成提速走轻量路线（2026-09-20 用户拍板：1 和 3 做、2 暂不做；方案 2 DeepSeek 官方端点等正式完工真实使用时可能接入）。根因实测：~60s 延迟 = prompt 预填充（小 prompt TTFT 4.6s；4k 字 27~32s；百炼端点无前缀缓存）。方案 1 = prompt 双档瘦身：闲聊/目标切换轮（OffTopic/GoalChange）只带模板人设 + 最近 2 条消息（单条 body ≤400 字，整包 ~1.5k 字）；学习轮保留 Summary/Gaps/Review/Memory/Source 证据、消息只带最近 2 条、掌握度与历史错误不再进证据（由确定性便签承载，便签已含 masteryScore/lastStuckPoint）。方案 3 = 等待呼吸态（见⑫）。
