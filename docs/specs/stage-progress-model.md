> 关联：反馈台账 BUG-001（进度面板改造 vs 挑战窗口固定进度设计的验证缺口）；
> 2026-09-28 路径不设限拍板（commit 01ae37f / 6e7bdb6）；死循环干预 v1（commit 4f02fdd）。
> 状态：设计稿 v2（2026-09-29 增补 §11 阶段内循环语义，源自朱曦策手绘六环节模型；
> 环节①单开《素材驱动阶段生成器》设计稿草稿）。待朱曦策过目拍板后动数据层代码。

## 1. 背景与问题

2026-09-28 的会话算法修改把学习路径从「固定路径」改成了「开放路径」：
引导卡「换条路」提供 agent / 网页 / 手动 / 演示 / 自定义五个出口，学生契约承诺
「路径数量与形式不设限，能圆回任务目标和验收就接住」。

这暴露了一个结构性矛盾：**现有进度语义隐含假设路径是固定的**。
当前进度是 participation 上的一个 `progress: int`（online_db/activity_store.py，
由 `ActivityProgressEvent` 推进），展示为「已加入 · 进度 N」。如果进度事件绑的是
「完成第 N 个任务 / 走到路径第 N 步」，用户一旦走了自定义路径，进度认定就失去依据，
「进度认定 vs 实际路径」之间会重新形成死循环——正是死循环干预要消灭的那类问题。

挑战窗口侧另有一个验证缺口（详见反馈台账 BUG-001）：挑战窗口是固定学习进度设计、
不经过普通会话创建的配置流程，进度面板改造后无法用挑战窗口验证普通创建流程是否正常。

## 2. 设计原则

1. **进度锚定「阶段验收证据」，不锚「路径步骤」**——进度只回答「这个阶段的目标产物 /
   验收证据拿到了没有」，不回答「你走了哪条路、走到第几步」。
2. **路径开放，只按大阶段约束**——路径数量与形式不设限（用户 2026-09-28 拍板）；
   约束只存在于大阶段粒度：阶段有先后顺序，阶段内路径自由。
3. **阶段 ↔ 任务是映射关系，不是固化结构**——任务改内容、增删任务只动映射，
   阶段表与进度语义不动。这就是「动态管理」的落点。
4. **「圆回来」是机器可判的**——任何路径（含跳级体验高阶段任务）产生的证据都记账，
   但阶段晋升要求本阶段及前置阶段的验收证据齐。提前跑 Lab B 可以，基线证据不补不晋升。
5. **阶段边界由课程结构定初版、由真实数据修正**——不拍脑袋，也不指望一步到位；
   调整依据来自埋点数据（见 §7）。

## 3. 数据模型

```
Stage {
  id            // 稳定标识，如 "s1"…"s6"，不因改名/重排变化
  name          // 展示名
  capability    // 能力目标（一句话，写清「学完能干什么」）
  evidence[]    // 验收证据清单：每条 = {kind, 描述, 判据}
  task_ids[]    // 覆盖的任务（映射，可改）
}

EvidenceEvent {
  stage_id, task_id
  kind          // 观察记录表 / 分界线总结 / 归类说理 / 纠错闭环 / eval 集 / checklist / 大考评分 …
  artifact_ref  // 证据载体引用（会话消息 / 文件 / 面板填写记录）
  path_tag      // 产生证据时走的路径（agent / web / manual / demo / custom），只记录不限制
  ts
}

ProgressState {
  current_stage        // 当前所处阶段
  evidence_by_stage    // stage_id -> 已齐证据
  stage_done[]         // 已晋升阶段
}
```

**晋升规则**：`stage_done += S_k` 当且仅当 `S_1..S_k` 的 `evidence[]` 全部有对应
`EvidenceEvent`。证据允许跨阶段超前记账（path_tag 如实记录），晋升严格按序。
旧的 `progress: int` 由 ProgressState 派生：`已完成证据数 / 总证据数`，保留兼容展示。

## 4. challenge-01 阶段划分（初版）

依据：17 天内容自带 stage_goal，且天然成对——单数日「AI 学生能说清 X」，
双数日「用户出题验证 + 误解纠错闭环」。六个大阶段：

| 阶段 | 名称 | 覆盖 | 能力目标 | 验收证据 |
|---|---|---|---|---|
| S1 | 亲历基线：人肉循环 vs agent 执行 | D1–D2 | 亲手跑过两种模式，说清分界线（循环谁跑、工具谁用、反馈谁看） | 观察记录表（Lab A/B 起，C/D 或降级）；分界线总结讲给 AI 学生 |
| S2 | 概念判据：LLM 调用 / workflow / agent | D3–D4 | 用「路径谁在运行时定」独立归类新场景 | 3 场景归类并说理（含灰色地带）；E1/E2 纠错闭环 |
| S3 | 核心机制：agent loop 与终止条件 | D5–D6 | 手画 loop 讲清每步输入输出，说清循环何时停 | loop 复述（卡壳点记录）；≥3 种终止条件并回扣 D1–D2 观察 |
| S4 | 工程接口：工具设计与上下文工程 | D7–D10 | 评审并修好工具定义，重写臃肿 prompt | 工具定义挑毛病并改对 + 角色互换一轮；prompt 重写 + ≥2 种压缩策略；E3/E4 纠错闭环 |
| S5 | 可靠性与评测：验证、人审、eval | D11–D14 | 说清外部验证边界，设计分层 eval 集 | 必须人审动作清单并说理；≥20 条分层 eval 集（每层防什么 + 期望输出）；E5/E6 纠错闭环 |
| S6 | 上线与综合：工程化与独立设计 | D15–D17 | 产出上线 checklist，独立完成完整 agent 方案 | 上线 checklist（逐项「防什么」+ 必需项排序）；D17 完整设计方案按评分尺打分；E7/E8 纠错闭环 |

划分逻辑对齐用户说的「先 prompt、再 harness」式递进：S1 先亲历（含 prompt 层的人肉循环），
S2 建判据，S3–S5 逐层进入 harness / 工程化内核，S6 综合产出。

## 5. 进度展示

- 创建会话时只按**大阶段粒度**展示与选择，不出细粒度任务进度。
- 面板文案：`阶段 2/6 · 概念判据 · 本阶段证据 1/2`；不再展示「任务 7/42」。
- SessionGoalDashboard 已有「名称 + 已完成/总数 + 百分比」的阶段标签行样式，直接复用，
  只把数据源从任务粒度换成阶段粒度。
- 挑战窗口的进度面板按挑战特化另做（BUG-001 后续方向③），本模型只定义数据语义。

## 6. 动态管理规则

- **任务内容修改**（如 Lab A 改多路径文案）：只动活动内容，阶段表与映射不动。
- **任务增删**：更新 `Stage.task_ids[]` 映射与对应 `evidence[]` 判据；阶段不动。
- **换路 / 自定义路**：证据照记（path_tag 如实标注），不影响认定。
- **跳级**：超前证据记账但不晋升，前置阶段证据补齐后自动追认。
- **阶段表本身的调整**（拆/并阶段）：属于版本变更，需记录调整原因与对应埋点依据（§7），
  不允许静默改——这正是「调整算法要有真实参考」的执行口径。

## 7. 埋点清单（算法调整的真实参考）

| 事件 | 来源 | 用途 |
|---|---|---|
| PATH_PREFERENCE 信号触发（含原文摘要） | ChatGuidance.kt 检测层 | 哪些任务/阶段的固定路径最容易引发抵触 → 内容层改造优先级 |
| detour 按钮点击（agent / web / manual / demo / custom） | 引导卡 testTags | 路径偏好分布 → 各任务该常备哪些路径选项 |
| 换路后证据是否最终补齐（圆回来率） | EvidenceEvent 对账 | 开放路径是否真的「能圆回来」；圆不回来的路径模式 → 契约/内容修正 |
| 阶段晋升耗时与卡点（证据缺口分布） | ProgressState 变迁 | 阶段边界是否合理：某阶段普遍卡 → 拆；某阶段秒过 → 并 |
| 跳级行为（超前证据） | EvidenceEvent path/stage 对账 | 阶段划分是否符合真实学习顺序 |

## 8. 与现有模型的迁移

1. 数据层新增 Stage / EvidenceEvent / ProgressState（不改旧表）；
2. 双写期：旧 `progress: int` 继续由旧事件推进，新模型并行记账；
3. 面板切到新模型渲染（普通会话创建流程先行）；
4. 验证通过后旧 int 改为派生值，旧事件停写。
挑战窗口在 ③ 之前保持固定进度设计不动（BUG-001）。

## 9. 验证策略与边界

- 进度面板改造的**唯一有效验证路径是普通会话创建流程**（BUG-001 结论）；挑战窗口的
  验证结果不能替代。
- 挑战窗口会话设计页的简单修改（策略锁定 + 进度特化）在会话算法定稿后进行。
- 合并正式版时按反馈台账逐条审计，本条（BUG-001）用普通创建流程验证关闭。

## 11. 阶段内循环语义（v2 增补，2026-09-29）

> 源自朱曦策手绘六环节模型：「书→目录→粗分类→阶段一/二/三；阶段一→问题⇄试探（不过回问题）；反馈→细分类路径→圆回阶段一」。
> 本章覆盖环节②～⑥；环节①（素材→粗分类）单开《素材驱动阶段生成器》设计稿。

### 11.0 层级边界（朱曦策拍板）

- **粗分类** = 阶段划分：**会话创建时**生成，定框架，是面板唯一展示粒度；
- **细分类** = 知识点级路径：**会话中增量发现**，逐知识点小循环产生，不预生成、不上面板、不写进创建时产物；
- 「动态管理」的准确含义 = 细分类在会话内逐知识点确定教学法路径，不是一次性全部做完、也不在创建时把路径写死。

### 11.1 六环节总览

| 环节 | 内容 | 归属 |
|---|---|---|
| ① | 素材→粗分类（阶段划分） | 创建时；单开设计稿 |
| ② | 入口问题（baseline_probe） | 会话内；§11.2 |
| ③ | 探针（三型） | 会话内；§11.3 |
| ④ | 反馈四岔口 | 会话内；§11.4 |
| ⑤ | 细分类·逐知识点小循环 | 会话内；§11.5（核心） |
| ⑥ | 圆回（阶段回放+晋升对账） | 会话内；§11.6 |

### 11.2 环节②：入口问题

- 每个阶段开场的第一个动作是把学生带进一个**场景化问题**，不是知识宣讲；
- 产物：`EvidenceEvent(kind=baseline_probe, stage_id, artifact_ref=学生第一次尝试的原文)`；
- 作用：基线证据（学生未经教学的原始状态）+ 自然引出阶段内容；
- 手绘图中的「不过回问题」指环节④的回环终点回到这里（重新出问题，不是重复宣讲）。

### 11.3 环节③：探针三型

- 三型：**复述型**（讲回来）、**迁移型**（换个场景再用一遍）、**挑错型**（指出 AI 故意埋的错）；
- 缺口驱动、一次一个：探针由当前知识点的缺口决定，不连发；
- 探针计划（probe plan）+ 判定口径（rubric）在**会话创建时**由 LLM 生成、随会话策略一起定稿——这就是全自动证据判定的落地形态（证据不事后补判，而是提前编入会话策略）；
- 学生提问 ≠ 路线意志：PATH_PREFERENCE 检测已有；问题用教学接住（先答双曲线，再圆回椭圆），意志才用路线接住（查前置 DAG，硬依赖走跳级通道）——改不改道只看证据链。

### 11.4 环节④：反馈四岔口

探针不过时先归因，再走岔口：

| 归因 | 判据 | 动作 |
|---|---|---|
| 理解性不过 | 字面能复述、逻辑讲不清 | 进环节⑤教学法降级链 |
| 知识性不过 | 前置知识点缺失 | 回环节②重新出问题（补前置后重进） |
| 表达性不过 | 懂但说不出 | 换探针型再试，不降级 |
| 存疑 | rubric 无把握 | 追问探针最多 3 轮 → 仍存疑则挂「待人工确认」标记，**不阻塞阶段推进** |

### 11.5 环节⑤：细分类——逐知识点小循环（核心）

以「阶段一教椭圆」为例：

1. 确定小循环路径第一步：**直接教学**椭圆相关内容 → 探针试探；
2. 不过 → 教学法降级链：**直接教学 → 类比/故事化 → 慢拆解 → 前置补课**，每降一档都出探针验证；
3. 学生在「故事化」档接受 → 确定「0→椭圆」这条细路径需要「故事」，完成第一个知识点记账；
4. 以此类推进入下一个知识点，直至阶段一全部知识点完成 → 环节⑥。

**教学偏好画像**：

- 某知识点的确认档（如故事化）**泛化为下一知识点的起步档**；
- 起步档过轻（秒过+主动加码「吃不饱」）才升档，避免来回震荡。

**细路径记账**（不上面板）：

```
{ 知识点, 起始档, 确认档, 尝试序列, 探针记录 }
```

用于画像与审计；面板仍只显示粗分类阶段（§5不变）。

### 11.6 环节⑥：圆回

- **阶段回放**：把本阶段知识点串成一条学生自己能复述的线（最后一个大探针 = 全局复述型）；
- **晋升结算**：按 §3 晋升规则对账（证据齐则 stage_done）；跳级超前证据只记账 path_tag、不晋升；
- **面板同步**：只更新粗分类阶段状态（BUG-001 边界仍适用——面板改造只在普通会话创建流程验证）。

### 11.7 角色中立性

六环节是角色无关的教学循环：

- **反转家教形态**：AI 学生出场景问题、装不懂要讲解（「我没听懂，能打个比方吗？」），用户讲解 = 证据来源；环节⑤的「教学」由用户完成，AI 负责探针与降级建议（「要不你试着讲个故事？」）；
- **直教形态**（学科会话）：AI 老师直接教学，探针由 AI 出；
- 证据判定只看 EvidenceEvent 的 kind 与 artifact_ref，不看谁在说话，两形态共用同一口径。
