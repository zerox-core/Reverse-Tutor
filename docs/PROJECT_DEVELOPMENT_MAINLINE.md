# Reverse Tutor 项目唯一主线开发宪章

> 版本：v1.0
> 生效分支：`newmp`
> 文档级别：项目开发流程与任务排序的最高优先级文档
> 生效日期：2026-08-30

## 0. 适用范围与优先级

本文件规定 Reverse Tutor 在 `newmp` 主生产分支上的唯一开发方式：

- 以拓扑结构组织产品能力；
- 以最小垂直切片交付用户价值；
- 以 TDD 作为每个切片的强制实现流程；
- 以契约层和横切能力保持前后端解耦；
- 以真实测试证据决定任务是否完成。

本文件不覆盖或削弱以下硬规则：

1. `AGENTS.md` 中的安全、编码、分支、密钥、冻结层和测试规则；
2. `mobile-native/core/model`、`core/protocol`、`core/llm`、`core/data`、Room、SecretStore 等冻结边界；
3. 用户在当前会话中明确提出的更高优先级安全或范围限制。

如果其他任务文档、Aily 指令或临时实现意见与本文件冲突，必须停止实现，先更新任务计划并取得明确确认。

## 1. 唯一主线原则

项目只允许一条产品主线：

```text
用户可用的普通会话
  → 上下文与学习算法
  → 结构化记忆拓扑
  → 子分支会话
  → heartbeat 主动对话
  → 学习事实与图谱投影
  → 最终视觉与副屏体验
```

不得同时开启互相独立、没有依赖关系的“页面先行”“图谱先行”“后台先行”路线。所有工作必须能回答：它在主线的哪个节点、依赖哪个上游、会为哪个下游提供稳定契约。

`main` 分支只作为旧行为和算法的参考来源；`newmp` 是唯一生产实现分支。不得将旧分支代码整体复制到新分支，也不得让 PWA/Capacitor 与 native Android 形成第三条产品主线。

## 2. 产品拓扑：能力的真实归属

### 2.1 窗口层级

```text
Space
├─ Companion Root
│  ├─ 全局人格与性格
│  ├─ 会话频率与交互偏好
│  ├─ 全局交互接口
│  └─ 默认 heartbeat
├─ Learning / Task Root
│  ├─ 一个明确的学习目标
│  ├─ 会话模板与学习策略
│  ├─ 本窗口局部上下文
│  └─ 学习结果可汇入全局学习档案
└─ Child Branch
   ├─ fork 时刻的不可变历史快照
   ├─ 自己的局部消息与 delta
   ├─ 默认关闭 heartbeat
   └─ 只能合并到直接父窗口
```

### 2.2 不可违反的拓扑规则

- `windowId` 与会话身份一致，不新增漂移的映射层。
- 子窗口只能看到 fork 时刻以前的祖先可见历史和自身消息。
- 父窗口 fork 之后的新消息、兄弟窗口消息不会进入子窗口。
- UI 时间线和生成上下文必须使用同一个可见历史投影。
- 继承消息是只读投影，不能删除、引用或写入长期记忆。
- 同级窗口不能互相合并；子窗口只能向直接父窗口合并。
- 合并后的父级结果不受下级分支后续修改影响。
- 没有真实结构化 delta 时，合并必须禁用，不得把普通聊天文本伪造成 delta。
- 根窗口 heartbeat 默认开启；子窗口只有显式命令才能开启。
- 隔离窗口的学习结果可以进入全局学习台账，但原始会话内容不能直接进入 companion memory。

## 3. 代码拓扑：唯一依赖方向

```text
UI / Screen
  ↓ 只消费 feature contract
Feature Port / UiState
  ↓ 只表达用户意图
App Wiring / Coordinator / Facade
  ↓ 组织跨模块流程
Domain Policy / Context Assembler / Planner
  ↓ 纯规则、纯数据、可测试
Repository / Runtime Adapter
  ↓ 领域安全模型
Room / Worker / Provider
```

强制规则：

- UI/feature 不得直接访问 DAO、Entity、Database、SQL、Worker、Provider、SecretStore。
- Provider 调用只能经过已发布 Runtime/Repository 路径。
- Worker 是后台 assistant 写入的唯一入口。
- 契约层不得包含 Compose、Android Context、导航对象、Room 类型或原始 Provider 错误。
- 新参数必须有安全默认值并保持向后兼容。
- UI 文案在 UI 层映射，不能为了显示中文改动 wire enum 或协议值。

### 3.1 后端能力先行，前端按能力适配

开发顺序不以当前前端页面、按钮或既有前端接口为牵引。后端的领域契约、策略、持久化、运行时和安全边界先独立设计并通过测试，再由前端根据已发布契约决定如何呈现和操作。

- 前端页面和按钮是后端能力的投影，不是能力定义来源。
- 临时前端只用于验证垂直链路，不得反向固化后端语义。
- 需要新增按钮时，先确认对应的后端命令、状态、权限和失败语义已经存在；没有稳定契约就先写能力申请或任务计划。
- 前端改版、布局替换和视觉延后，不得阻塞后端算法、记忆、心跳、持久化和安全能力建设。
- 如果前端需求要求改变领域语义，必须先更新契约与测试，再安排适配层修改。

## 4. 最小垂直切片定义

任何新任务都必须同时覆盖以下九层，缺一层就不能称为“完成”：

```text
用户入口
→ Feature 契约
→ App 编排
→ Domain 算法
→ 持久化读写
→ Runtime / Provider
→ UI 状态投影
→ 自动化测试
→ 最小设备验收
```

每个切片必须提供：

1. 一个用户可触发的入口；
2. 一个明确的成功结果；
3. 一个明确的失败结果；
4. 一条可追踪的数据流；
5. 重启或重新进入后的状态恢复；
6. 与上游、下游交接用的稳定契约；
7. 不依赖视觉细节的语义验收方式。

“只写接口”“只写页面”“只写数据库”“只写测试”都属于未完成的准备工作，不得作为产品功能完成汇报。

## 5. TDD 强制循环

每个垂直切片必须严格执行以下顺序：

### 5.1 Red：先写失败测试

- 测试描述用户行为或边界规则，而不是实现细节。
- 测试必须先失败，且失败原因与目标缺口一致。
- 测试不能通过删除断言、放宽条件、吞异常或伪造返回值来“预先通过”。

### 5.2 Green：最小实现

- 只实现让失败测试通过所需的最小生产代码。
- 不在同一轮顺便重构无关模块。
- 不跨越冻结层；若契约确实不足，先创建能力申请并停在审批门。

### 5.3 Refactor：保持边界

- 消除重复和明显耦合，但不得改变已确认的契约语义。
- 检查 UI 是否仍只依赖 Port/UiState。
- 检查上下文、时间线、写入者和窗口边界是否仍保持一致。

### 5.4 Acceptance：真实验收

按风险从低到高执行：

1. 定向 JVM 测试；
2. 受影响模块回归；
3. 全量 Android test/lint/build；
4. Python 回归（涉及 Python 或跨线行为时）；
5. 一次可用模拟器或主力真机验收。

设备未连接、安装未完成或测试被环境拦截时，状态必须写成 `blocked`/`not_run`，不能用 JVM 结果冒充设备证据。

## 6. 唯一产品开发顺序

### V0：基线和拓扑门禁

固定窗口身份、space 归属、可见历史、记忆分区、heartbeat 默认值和冻结边界。所有后续任务先引用这些规则。

### V1：普通单会话最小闭环（当前最高开发优先级）

```text
模板创建
→ 学习策略
→ 当前窗口上下文
→ Qwen/百炼生成
→ assistant 回复
→ 轮次持久化
→ 结构化学习结果
→ 重启恢复
```

V1 完成前，不再扩展图谱视觉、复杂分支树或大规模副屏。

### V2：记忆拓扑

接入 companion memory、learning memory、局部任务记忆和演进版本。模板提供初始设定，每轮只产生有界结构化候选，不保存 raw transcript。

### V3：子分支窗口

接入 fork 快照、隔离时间线、直接父级导航、局部 delta 和安全删除/合并能力。没有完整删除能力时必须禁用删除成功路径。

### V4：heartbeat 主动对话

由上下文、记忆和资格策略生成 InitiativePlan，再由 Worker 执行。禁止用空消息模拟 heartbeat，禁止新增第二条 assistant 写入路径。

### V5：学习事实与图谱投影

图谱只消费结构化学习事实、证据和掌握度变化；图谱不是聊天算法、记忆算法或 Provider 调度器。

### V6：最终前端与副屏视觉

前端可替换布局、色彩、组件和动画，但必须继续消费 V1–V5 发布的契约。视觉验收不能反向改变后端数据语义。

## 8. Aily/协作者交接格式

任何交接任务必须包含：

```text
任务编号：
所属主线节点：
上游依赖：
允许修改路径：
禁止修改路径：
Red 测试命令与预期失败：
Green 实现范围：
回归命令：
设备验收命令：
失败时停止条件：
交付文件与证据：
```

协作者不得自行改变任务顺序、扩大范围、提交冻结层变更或把未执行的设备测试写成通过。所有不确定性必须回到主控确认。

## 9. 任务完成与提交门禁

任务只有在以下条件全部满足时才能标记 `completed`：

- Red/Green/Refactor 过程有真实记录；
- 定向测试通过；
- 受影响模块回归通过；
- 全量回归结果已记录，或明确记录阻塞原因；
- `git diff --check` 通过；
- 冻结路径检查无未批准改动；
- 无敏感信息进入代码、日志、文档或提交；
- 设备证据按真实状态记录；
- 前端交接契约已写入项目文档；
- 未完成能力没有被 UI 伪装成成功。

默认不自动 `commit`、`push` 或打 tag。只有用户明确要求时才执行，并使用版本化提交说明和可追踪验收证据。

## 10. 停止条件

出现以下任一情况必须停止当前任务：

- 需求、范围、契约、数据结构或默认值存在未确认的多种解释；
- 需要修改冻结层但没有对应批准；
- 测试失败原因不明或连续重复失败；
- 设备证据无法获得；
- 删除、合并、heartbeat 或 assistant 写入语义无法证明安全；
- 发现旧分支行为与当前契约冲突；
- 构建环境、缓存或设备状态可能污染另一项目。

停止时必须给出：已确认事实、阻塞原因、禁止的假修复、下一项最小判别实验。

## 11. 文档维护规则

- 本文件是开发顺序、TDD 和垂直切片的唯一主线来源。
- 具体功能规格可以补充本文件，但不能改变主线顺序和硬性门禁。
- 若产品方向变化，先更新本文件，再更新执行计划，最后才改代码。
- 每次出现可复现的开发问题，必须同步更新开发防回归问题登记。
- 前端设计文档、图谱视觉稿和 Aily 任务单都必须引用本文件中的主线节点。
